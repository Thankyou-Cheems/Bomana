# Bomana v6.8.0 开发方案（架构修订版）：HUD 全屏叠加层

> 基于当前源码 `v6.8.0` 与现有模块边界修订  
> 日期：2026-02-12

---

## 0. 评估结论（先给结论）

原方案方向正确，但需要做三类取舍：

### 0.1 保留（可直接推进）

- 全屏透明 HUD 叠加层（Windows）
- 置顶 + 点击穿透 + 锁定/解锁机制
- 主目标方向/距离/格子坐标的直观显示
- 8111 抖动容错、降级提示、性能守护

### 0.2 调整（避免重复造轮子）

- 不新增 `core/navigation.py`，优先复用 `GameLogic -> UISnapshot` 现有导航结果
- 不新增 `state.hud_data` 持久状态字段，HUD 为 UI 层消费快照
- 不引入第二套轮询频率；继续使用现有 `NetworkConfig.POLL_INTERVAL=0.05`
- 不用 `Ctrl+H`（当前热键系统是 F1-F12）；改为新增可配置功能键（默认 `F12`）

### 0.3 延后（当前数据/风险不匹配）

- “目标在视野内菱形框住目标区域”：需要视角/FOV/俯仰等可靠投影输入，Phase 1 不做
- “目标高度差”：战区目标通常无稳定高度语义，暂不做
- “地面目标群自动分类”：当前需求核心是战区定位，先不扩功能边界

---

## 1. 产品目标与边界

### 1.1 目标用户

- 老式飞机（低 BR）玩家，缺少机载导航辅助
- 需求是“抬头就知道战区方向”，减少切地图频率

### 1.2 目标定义（v6.8.0）

- 在不突破 8111 合规边界的前提下，提供“方向感优先”的 HUD 叠加层
- 首版优先解决“找到战区”与“持续修正航向”

### 1.3 非目标

- 不做自动驾驶/自动投弹/输入注入
- 不做敌情增强或超出 8111 公开数据的信息推断

---

## 2. 技术方案（按现有架构落地）

## 2.1 模块落点

仅新增 UI 模块，核心逻辑尽量不动：

```
bomana/
├─ ui/
│  ├─ app.py               # 修改：HUD 生命周期、开关、更新入口
│  ├─ dialogs.py           # 修改：HUD 设置项（Phase 2）
│  ├─ nav_window.py        # 不改功能边界（保持现有独立导航条）
│  └─ hud_overlay.py       # 新增：HUD 窗口 + Canvas 渲染
├─ config.py               # 修改：HUD 配置 + Hotkey 扩展（F12默认）
└─ utils/
   └─ system.py            # 复用 Win32.setup_window / 多显示器工具
```

## 2.2 数据流（关键决策）

- HUD 不直接读 8111，不新增 fetcher
- HUD 直接消费 `UISnapshot`：
  - `snap.player_heading`
  - `snap.zones`（含 `is_target`, `relative`, `distance_km`, `grid`）
  - `snap.api_down`, `snap.phase`
- 这样可与现有导航目标选择算法保持一致，避免主界面与 HUD 显示冲突

## 2.3 模式策略（与现有 `navigation_mode` 协同）

- 保留 `navigation_mode = integrated | standalone`
- 新增独立布尔开关：`hud_enabled`
- 含义：HUD 是“叠加显示层”，不是替换现有导航模式
- 默认行为：`hud_enabled=False`，用户主动开启

## 2.4 热键策略

- 新增 `HotkeyConfig.KEY_HUD`（默认 `F12`）
- 纳入本地热键与全局热键注册链路
- 在设置面板中可改键（与现有 F 键体系一致）

## 3. HUD 显示规则（可实现版本）

## 3.1 主目标选择

- 主目标 = `snap.zones` 中 `is_target=True` 的战区
- 若无主目标则降级为“最近前方目标”，仍无则显示“无可用目标”

## 3.2 元素布局

- 屏幕中心安全区：默认 40% 区域不绘制文本块
- 方向箭头：贴边显示（上/左/右/下），由 `relative` 决定
- 信息文本：`grid + distance + relative`

## 3.3 状态规则

- 正常：绿色
- 接近（<=5km）：黄色
- 近距（<=2km）：红色 + 1Hz 闪烁
- 数据延迟（连续超时或 `snap.api_down`）：半透明 + “8111 数据延迟”角标

## 3.4 明确不做（v6.8.0）

- 不做“视野内菱形投影框”
- 不做“高度差”
- 不做“敌方目标增强图层”

---

## 4. 性能与稳定性策略

## 4.1 帧与更新

- 复用主 UI 刷新节拍（50ms，20FPS）
- HUD 只在 `hud_enabled=True` 时更新

## 4.2 渲染策略

- 禁止每帧 `delete+create` 全量重绘
- 采用“对象复用 + `coords/itemconfig` 差量更新”
- 角度变化阈值触发重绘（如 >0.5°）

## 4.3 降级路径

- 无目标：显示简短待机提示
- 8111 抖动：保留最后有效目标短时显示，随后进入“延迟态”
- 窗口样式失败：降级到 Tk `-alpha`，功能可用优先

## 4.4 多显示器策略

- Phase 1：默认跟随主窗口所在显示器
- Phase 2：增加显示器选择或“跟随鼠标所在屏”选项

---

## 5. 合规与风险控制

## 5.1 红线

- 仅用 `/indicators` `/state` `/map_obj.json` `/map_info.json`
- 不读内存，不注入，不改游戏文件，不发输入

## 5.2 争议控制（重点）

参考官方论坛口径，避免“ESP 化”观感：

- v6.8.0 首版仅突出“当前导航目标”
- 不提供超出当前导航面板的信息密度
- 配置页增加风险提示与开关默认关闭

---

## 6. 里程碑（修订后）

## Phase 1（MVP，3-4天）

目标：可用、稳定、不分叉现有架构。

交付：
- `ui/hud_overlay.py`：全屏透明窗口、点击穿透、基本箭头/文本
- `ui/app.py`：HUD 开关、生命周期、快照更新接入
- `config.py`：`hud_enabled`、HUD 样式基础项、`KEY_HUD`

验收：
- 可热键开关 HUD
- 可在游戏上方稳定显示主目标方向与距离
- 8111 抖动不崩溃
- 明显不影响主窗口流畅度

## Phase 2（可用性增强，3-5天）

交付：
- 顶部简化罗盘条（可开关）
- HUD 设置项（颜色/透明度/信息层级/显示器策略）
- 文本避让和多目标（最多2-3）

验收：
- 20FPS 稳定
- 多目标不遮挡中心视野
- 设置项持久化并可即时生效

## Phase 3（发布打磨，2-3天）

交付：
- 压力与长稳测试
- 文档与变更日志
- 异常路径回归

验收：
- 连续运行 30 分钟无明显对象泄漏
- 1080p/1440p/4K 可读性可接受
- 发布说明与风险提示完整

## 7. 可执行任务清单（实现导向）

1. `config.py`：新增 HUD 配置结构与默认值；扩展热键绑定（`hud`）。
2. `ui/app.py`：新增 HUD 初始化/销毁/显示开关；接入全局热键注册。
3. `ui/hud_overlay.py`：实现窗口样式、点击穿透、显示器定位。
4. `ui/hud_overlay.py`：实现对象复用渲染器（箭头/文本/状态角标）。
5. `ui/app.py`：在 `_update_ui` 中喂入 `UISnapshot`，做阈值更新。
6. `ui/dialogs.py`：新增 HUD 设置（Phase 2）。
7. 手测矩阵：全屏独占/无边框、单屏/双屏、锁定/解锁、8111断连恢复。
8. 文档更新：`docs/CHANGELOG.md` + `README.md`（HUD开关与合规提示）。
